# 국내 주식 관심종목 앱

이든크루 Flutter 과제 1. 관심 · 검색 · 종목상세 세 화면을 네이버 데이터로 구현했습니다.
요구사항은 [`docs/ASSIGNMENT.md`](docs/ASSIGNMENT.md), 데이터 연동 가이드는 [`docs/NAVER_API.md`](docs/NAVER_API.md)에 있습니다.

## 실행 방법

- Flutter **3.44.0** (FVM으로 고정, `.fvmrc`)

```bash
fvm flutter pub get
fvm flutter run          # Android / iOS / 데스크톱. 웹(Chrome)은 네이버 CORS 때문에 동작하지 않습니다.
fvm flutter analyze
fvm flutter test                                  # 단위 · 위젯 테스트 (네트워크 없음)
fvm flutter test integration_test -d <기기 id>    # 종합 테스트 (기기 + 실제 네이버 응답)
```

- 확인한 플랫폼과 기기: Android 에뮬레이터 (Pixel 10, Android 17 / API 37), 실제 네이버 데이터로 관심 · 검색 · 상세 전체 흐름 확인
- 폰트: 스타터에 등록된 `Noto Sans KR`을 그대로 사용합니다.

모두 구현했습니다.

### 선택

- 관심: Pull to refresh, 스와이프 삭제, 관심 목록 로컬 저장, 정렬 기준 · 방향 앱 재실행 후 유지
- 검색: 입력 디바운스(300ms), 검색 중 로딩 표시, 최근 검색어, 토스트 등장 · 퇴장 애니메이션
- 상세: 차트 가격 축 · 거래량 막대, 차트 영역 채우기, 크로스헤어 · 툴팁, 차트 전환 애니메이션, 일별 시세 표 10행씩 펼치기
- 전체: 실시간 시세 자동 갱신

선택 항목까지 모두 구현했습니다.

`fvm flutter test` → **55개 모두 통과**

- 시세 숫자는 매번 달라서 값이 아니라 화면 상태 · 표기 형식 · 캔들 개수만 확인합니다. 기기 저장소와 섞이지 않게 빈 저장소로 시작합니다.
- 단위 · 위젯 테스트는 네트워크 없이 `test/mocks/`의 가짜 저장소(`FakeStockRepository`, 요청을 기록하는 `RecordingStockRepository`)로 돌립니다.

- 네이버 응답 파싱: `assets/mock/`에 저장한 실제 응답 4종(일별 시세 HTML은 EUC-KR 원본 그대로)으로 검증. 일별 시세는 전일비 부호가 종가 차이와 맞는지까지 확인
- 일별 시세 페이지를 필요한 만큼만 받고 재사용하는지, 실패 페이지를 다시 받는지, 다시 들어올 때 1페이지만 새로 받고 날짜가 바뀌었으면 전부 다시 받는지
- 정렬(시세 없는 행 위치 포함, 재실행 후 유지), 검색 응답 순서 역전, 자동 갱신 주기 · 정지 조건, 토스트 스택, 로컬 저장, 화면 위젯 테스트
- 세 화면 관심 동기화(검색 등록 → 목록 추가 → 상세 해제 → 목록 · 검색 별)를 가짜 저장소로도 확인(`test/favorite_sync_test.dart`). 종합 테스트와 같은 흐름을 네트워크 없이 돌립니다.
- 일별 시세: 차단 · 안내 페이지(표 없음)는 실패 처리, 페이지를 4개씩 나눠 요청, 행이 밀린 뒤 이어 받아도 날짜가 겹치지 않는지
- 글자 크기 최대(1.3배)에서 상세 화면이 넘치지 않는지, 헤더 버튼 · 별의 누르는 영역(48 이상)과 아이콘 위치, 등락률 반올림(201 / 20,000 → `+1.01%`)

## 기술 선택과 이유

### 상태관리: Riverpod 3

- 관심 목록은 세 화면이 같이 보는 상태라 전역에서 하나로 관리해야 합니다. `NotifierProvider` 하나로 동기화 요구사항이 해결됩니다.
- 저장소를 provider로 주입해서 테스트에서 `overrideWithValue(FakeStockRepository())`(`test/mocks/`)로 바꿔 끼웁니다. 네트워크 없이 모든 화면을 테스트할 수 있습니다.
- 상세 화면은 `autoDispose.family`(종목코드별)라서 화면을 나가면 상태와 자동 갱신 타이머가 같이 정리됩니다.
- 탭 인덱스처럼 한 화면에서만 쓰는 UI 상태는 `StatefulWidget`에 둡니다.

### 구조

```text
lib/
  data/        dto/ (서버 응답 그대로), repository/ (저장소 인터페이스 · 네이버 구현, 일별 시세 페이지 로더)
  features/    watchlist/ · search/ · detail/ — 화면, ViewModel(Notifier), UI 모델, 위젯
  shared/      Result, 포맷, 등락 방향, 공통 위젯(토스트 · 빈 상태 등), 관심 목록 · 저장소 상태
  app/         하단 탭 셸
  theme/       스타터 디자인 토큰 (값은 수정하지 않음, 서체 조합만 추가)
test/mocks/    테스트용 가짜 저장소 (FakeStockRepository, RecordingStockRepository)
```

- 데이터 계층은 종류별, 화면은 기능별로 묶었습니다.
- 타입은 지역 변수 · 컬렉션 리터럴 · 람다 파라미터 · 패턴(`Success<StockMetaDto>(...)`)까지 모두 적습니다. 리뷰로만 지키면 빠지는 곳이 생겨서 `analysis_options.yaml`에 `always_specify_types` 린트를 켜 `flutter analyze`가 잡게 했습니다.
- **DTO와 UI 모델을 분리**했습니다. DTO는 서버 응답을 그대로 담고, 등락액 · 등락률 · 시가총액 계산과 여러 DTO 합치기(메타 + 시세)는 UI 모델의 `from()`에서 합니다. 서버 모양이 바뀌어도 위젯은 그대로입니다.
- 저장소는 예외를 던지지 않고 `Result`(`Success` / `Failure`)를 돌려줍니다. 뷰모델이 `switch`로 받아서 화면마다 맞는 상태로 바꿉니다.
  - 관심: 이미 받은 시세는 두고 배너만 띄우므로 `hasError`
  - 검색: 결과 · 로딩 · 실패가 서로 배타적이라 `SearchStatus`
  - 상세: 종목 정보 · 현재가 실패는 화면을 그릴 수 없어 `AsyncError`(화면 전체 다시 시도), 일별 시세만 실패하면 `hasPeriodError`(차트 자리만 다시 시도)
  - 에러 종류(네트워크 · 차단 · 파싱)는 나누지 않았습니다. 지금은 모든 실패를 "다시 시도"로 똑같이 안내해서 종류를 쓰는 화면이 없습니다. 종류별 안내가 필요해지면 저장소의 `_get` 한 곳에서 분류하면 됩니다.
- 기기 저장소(`SharedPreferences`)는 관심 목록 · 최근 검색어 · 정렬 기준처럼 문자열 몇 개라 별도 저장소 계층 없이 각 Notifier가 `preferencesProvider`로 직접 읽고 씁니다. `main`에서 override하고, 테스트처럼 override가 없으면 메모리에만 둡니다.

| 패키지 | 이유 |
| --- | --- |
| `flutter_riverpod` | 상태관리 (위) |
| `http` | GET 4개면 충분해서 가벼운 공식 패키지. 테스트는 `MockClient` |
| `html` | 일별 시세가 HTML이라 DOM으로 파싱. 정규식보다 공백 · 속성 순서 변화에 안전 |

### 일별 시세 페이지 요청 (`DailyPriceLoader`)

- 1페이지를 먼저 받아 `lastPage`를 알아낸 뒤, 기간에 필요한 페이지(`거래일 ÷ 10` 올림, `lastPage` 이하)를 **4개씩 나눠** 요청합니다. 1년(25페이지)을 한꺼번에 보내면 같은 호스트에 요청이 몰려 느려지거나 차단될 수 있어서입니다. 하나라도 실패하면 남은 페이지는 요청하지 않습니다.
- 캐시에 결과가 아니라 **요청 `Future`를 저장**합니다. 받는 중인 페이지를 다시 요청해도 새 요청을 보내지 않습니다. 1개월 → 3개월로 바꾸면 3~6페이지만 새로 받습니다.
- 실패한 페이지는 캐시에서 지워서 다음에 다시 받습니다. 표가 없는 응답(차단 · 안내 페이지)도 빈 페이지가 아니라 실패로 처리해서, 빈 차트가 캐시에 남지 않고 다시 시도가 뜹니다.
- 합칠 때 날짜로 중복을 거릅니다. 상세 화면을 연 채로 새 거래일 행이 생긴 뒤 탭을 바꾸면, 캐시된 앞 페이지와 새로 받은 뒤 페이지가 한 행씩 어긋나 경계에서 같은 날짜가 두 번 오기 때문입니다(이 경우 그 기간은 한 행 짧게 보이고, 다음에 상세 화면에 들어오면 아래 규칙으로 캐시를 새로 받습니다).
- **상세 화면에 들어올 때마다 1페이지만 새로 받고**, 맨 위 행의 날짜를 캐시와 비교합니다. 기간 탭을 바꿀 때는 요청 없이 캐시만 씁니다.
  - 날짜가 같으면 행이 밀리지 않은 것이라 1페이지만 바꿉니다. 장중에 다시 들어오면 차트의 오늘 캔들이 최신값이 됩니다.
  - 날짜가 다르면 새 거래일 행이 맨 앞에 붙어 **모든 페이지가 한 칸(한 행)씩 밀린** 것입니다. 옛 2페이지를 이어 붙이면 경계에서 날짜가 겹치거나 빠지므로 그 종목 캐시를 전부 버립니다.
  - 기기 시계가 아니라 서버 데이터의 날짜로 판단해서, 주말처럼 날짜는 바뀌어도 새 거래일이 없으면 캐시를 그대로 씁니다.
  - 처음 들어올 때는 캐시가 없어 어차피 1페이지를 받으므로 추가 요청이 없습니다. 새로 받기에 실패하면 캐시를 그대로 보여줍니다.

### 차트: `CustomPainter`

- 캔들 색(`chartLineUp` / `chartLineDown`), 축 · 거래량 · 영역 색 토큰과 시안 여백을 그대로 맞추려면 직접 그리는 편이 정확했습니다.
- 크로스헤어 · 툴팁도 같은 좌표계에서 계산하므로 패키지 없이 간단합니다.

### 디자인 토큰

- **토큰 값은 수정하지 않았고, 색 · 간격 토큰도 추가하지 않았습니다.** 색은 모두 `context.colors.*`, 간격(여백 · 반경 · 아이콘 크기)은 `context.dimens.*`를 씁니다.
- **서체 조합 5종(`AppTypography.regular11 / regular13 / medium15 / bold13 / bold19`)을 추가했습니다.** Figma가 서체 · 굵기만 변수로 두고 크기 · 행간은 텍스트 레이어마다 적혀 있어서, 두 곳 이상 반복되는 조합만 한 곳에 모았습니다. 이유와 대응표는 [`lib/theme/README.md`](lib/theme/README.md#앱-전용-추가-토큰-figma-변수-아님)에 있습니다.
- 토큰에 없는 **컴포넌트 크기**는 시안 값을 그 위젯의 상수로 둡니다. 한 곳에서만 쓰는 값이라 토큰으로 올리지 않았습니다.

| 위젯 | 값 |
| --- | --- |
| 관심 헤더 / 상세 헤더 높이 | 52 / 55 |
| 검색 입력창 · 기간 탭 높이 | 40 · 28 |
| 검색 결과 행 · 최근 검색어 행 · 일별 시세 행 높이 | 60 · 48 · 32 |
| 토스트 높이 · 차트 높이 | 46 · 200 |
| 관심 행 서체 (종목명 · 가격 / 종목코드 · 등락) | 16/20 medium · 12/16 regular, 두 줄 간격 2 |
| 빈 상태 · 다시 시도 아이콘 / 정렬 체크 아이콘 | 40 / 24 |
| 현재가 서체 | Bold 30/36 |

## 직접 판단한 부분과 이유

### 토스트

- **최대 3개까지 쌓이고**, 새 토스트가 맨 아래에 붙습니다. 넘치면 가장 오래된 것부터 지웁니다.
- 각각 **2초** 뒤 사라지고, **탭하면 바로** 닫힙니다. 문구가 10자 정도로 짧아서 2초면 충분합니다.
- 별을 여러 번 눌렀을 때 직전 동작들이 같이 보이도록 쌓는 방식을 택했습니다. `SnackBar`는 한 번에 하나만 보여줄 수 있어 `ToastHost`로 직접 구현했습니다. 탭 바 바로 위에 뜹니다.
- 관심 등록 · 해제 토스트는 검색뿐 아니라 **관심(스와이프 해제) · 상세 화면에서도** 뜹니다. 상세는 탭 화면 위에 쌓이는 화면이라 탭 화면의 `ToastHost` 밖에 있어서, 상세 route를 자체 `ToastHost`로 감싸 화면 하단(시스템 제스처 영역 위)에 띄웁니다. 앱 전체를 하나로 감싸지 않은 이유는 탭 화면에서 토스트가 탭 바를 가리지 않고 그 위에 떠야 하기 때문입니다.
- **키보드가 올라와 있으면 키보드 바로 위에** 뜹니다. 탭 화면은 `Scaffold`가 body를 키보드 위로 줄여 주고, 상세처럼 `Scaffold` 바깥을 감쌀 때는 제스처 바와 키보드 높이 중 큰 쪽만큼 올립니다. 두 경우 모두 키보드 높이를 준 위젯 테스트로 확인했습니다.

### 로딩

- 관심: 시세를 못 받은 행만 스켈레톤(`feedbackSkeleton` 단색). 목록 전체를 가리지 않습니다.
- 상세 첫 진입: 레이아웃 모양의 스켈레톤. 기간 전환 중에는 **이전 차트 · 표를 흐리게(0.4) 남기고** 스피너를 띄워 화면이 깜빡이지 않게 했습니다.
- 검색: 첫 결과 전에는 가운데 스피너, 결과가 있으면 위쪽 얇은 진행 막대(결과를 지우지 않음).

### 네트워크 에러

- 관심: 상단 배너(`정보를 불러오지 못했습니다` + 다시 시도). 이미 받은 시세는 그대로 둡니다.
- 검색: 에러 화면 + 다시 시도.
- 상세: 종목 정보 · 현재가를 못 받으면 화면 전체 다시 시도. **일별 시세만 실패하면** 현재가 · 요약은 보여주고 차트 자리에만 다시 시도를 띄웁니다.

### 긴 종목명

말줄임(`…`) 처리합니다. 관심 행에서는 이름만 줄고 오른쪽 가격 영역은 밀리지 않습니다.

### 기기 글자 크기

기기의 글자 크기 설정은 따르되 **1.3배까지만** 키웁니다. 헤더 · 기간 탭 · 검색 입력창 · 토스트가 시안 높이로 고정되어 있어서, 2배에서는 상세 헤더가 13px, 현재가 행이 64px 넘쳤습니다. 1.3배에서 7자리 가격 종목의 상세 화면이 넘치지 않는 것을 위젯 테스트로 확인했습니다.

### 누르는 영역

아이콘은 시안 크기(20)로 그리고, **누르는 영역은 48 이상**으로 넓혔습니다. 20 × 20만 눌리면 조금만 벗어나도 반응하지 않고, 검색 결과 행에서는 별을 살짝 비껴 누르면 관심 등록 대신 상세 화면이 열렸기 때문입니다.

- 뒤로 가기 · 새로고침: 헤더 높이 전체 + 헤더 여백 · 옆 간격까지 누르는 영역입니다. 헤더 여백을 버튼 안쪽 여백으로 옮겨서 아이콘과 종목명 위치는 시안과 같습니다.
- 별: 48 × 48. 늘어난 만큼 오른쪽으로 옮겨 아이콘 끝이 화면 여백 선에 맞습니다.
- 정렬 칩: 높이 44.
- 아이콘 · 종목명 위치가 바뀌지 않았는지 위젯 테스트로 확인합니다.

### 등락률 반올림

등락률은 정수(등락액 × 10,000 ÷ 전일 종가)로 계산해 표기 자리(소수 둘째 자리 %)에서 반올림합니다. `double`로 나눈 뒤 반올림하면 201 / 20,000이 1.00499…%가 되어 `+1.01%`가 아니라 `+1.00%`로 표시됩니다. 거래량 `천` · 시가총액 `조/억` 축약은 시안 표기(`1,063조`)에 맞춰 버림입니다.

### 시세를 못 받은 행의 정렬

현재가순 · 등락률순에서 값이 없는 행은 **역순이어도 항상 맨 아래**에 둡니다. 비교할 값이 없으니 순위에 끼지 않는 게 맞고, 방향을 바꿀 때 스켈레톤 행이 위아래로 튀지 않습니다.

### 실시간 시세 자동 갱신

- 네이버 실시간 시세는 SSE · WebSocket이 없는 폴링 API이고, 응답에 서버가 권장하는 주기(`pollingInterval`, 7초)가 들어 있어 그 값을 따릅니다.
- **화면이 안 보일 때**(다른 탭, 상세 화면이 위에 있음), **앱이 백그라운드일 때**, **모든 종목이 장 마감(`ms != OPEN`)일 때**는 멈춥니다. 다시 보이면 바로 한 번 조회합니다.
- 상세 화면은 종목 정보를 재사용하고 현재가만 다시 받습니다.

### 그 외

- 관심 목록은 **빈 목록으로 시작**하고 기기에 저장합니다. 첫 화면 전에 저장값을 읽어 빈 상태가 잠깐 보이는 깜빡임이 없습니다.
- 가나다순은 한글 이름이 먼저, 영문 · 숫자로 시작하는 이름이 뒤에 옵니다.
- 결과 없음 문구의 검색어는 20자에서 자릅니다(글자 단위라 한글 · 이모지가 깨지지 않음). 시안의 2줄 문구가 항상 보이게 하려는 것입니다.
- 최근 검색어는 **검색 결과를 눌렀을 때만** 저장합니다(디바운스 중간 글자가 쌓이지 않게). 최대 5개, 같은 검색어는 맨 위로 올립니다.
- 검색 결과의 시장명은 자동완성 응답의 `typeName`을 씁니다. 결과마다 메타데이터 API를 부르면 요청이 결과 수만큼 늘어나서, 메타데이터는 관심 · 상세에서만 씁니다.

### Figma와 다른 부분

- 정렬 칩에 방향 화살표(↓/↑)가 있고, **같은 기준을 다시 고르면 역순**이 됩니다. 내림차순만 있으면 '많이 떨어진 종목'을 볼 방법이 없어서 추가했습니다.
- 최근 검색어 목록, 스와이프 삭제 배경, 차트 축 · 거래량 · 툴팁은 시안에 없어 기존 토큰으로 구성했습니다.
- 일별 시세 표는 10행부터 보여주고 스크롤하면 **선택한 기간 안에서** 10행씩 펼칩니다. 기간을 넘지 않으므로 '탭을 바꾸면 표 기간도 바뀐다'는 요구사항은 그대로입니다.

## 막혔던 지점과 접근

- **EUC-KR 응답**: 실시간 시세 · 일별 시세가 `charset=EUC-KR`로 옵니다. `http`의 `response.body`는 모르는 charset을 latin1로 읽어서, `bodyBytes`를 `charset` 패키지로 직접 디코딩했습니다.
- **일별 시세 HTML**: 전일비 칸의 숫자에는 부호가 없고 방향이 아이콘 클래스(`bu_pup` / `bu_pdn`)와 숨김 글자(상승 · 하락)로만 나옵니다. 두 가지로 부호를 정합니다. 마지막 페이지는 '맨뒤' 링크, 없으면 페이지 링크 중 최댓값입니다.
- **개발 네트워크에서 일부 도메인 차단**: 작업한 PC 네트워크에서 `finance.naver.com` · `stock.naver.com` · `ac.stock.naver.com`만 TLS 연결이 끊겼습니다. 같은 IP에 HTTP는 되고 SNI만 바꾸면 HTTPS도 되는 것으로 보아 SNI 기반 차단이었습니다. 처음에는 받을 수 있던 실시간 시세만 실제 응답으로, 일별 시세는 페이지 구조를 옮긴 샘플로 테스트했고, 네트워크를 바꾼 뒤 실제 응답을 `assets/mock/`에 저장해 다시 검증했습니다.
